# Demo Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use `- [ ]`.

**Goal:** A presenter screen (`/demo`) that walks ONE load through the real systems — uncovered load → AI recommendation → human approval (real assignment) → simulated transit → a scripted breakdown that Night Shift detects and handles in shadow mode → escalation with a proposed customer update → dispatcher resolution → delivery — with a **Reset Demo** button that recreates the exact known state every time.

**Architecture:** a thin backend orchestrator (`src/lib/demoStory/`) that owns the demo fixtures and the story state (`DemoStory` row per org), observes the real systems (AI run rows, assignment/sim state, Night Shift's `AgentTrip`/`AgentEvent` rows, load status) on every poll, triggers the two scripted world events (the breakdown, the dock hold) through the simulation's own mode/ping mechanisms, and proxies the driver's reply to the worker's real driver-link endpoint. Human actions go through the EXISTING dispatcher endpoints from the portal (assignment creation, agent switch, agent command) — the orchestrator records them. No change to Night Shift, the dispatch engine, the loop, the simulation engine or the seed.

**Spec:** the approved design (this conversation, 2026-09-28) + three adjustments: (1) the demo customer's email is a controlled sink (`demo-customer@example.invalid`) and the demo policy is shadow — no message can leave the system; (2) Reset is idempotent and total; (3) `/demo` is a presenter screen: ten business stages in plain language, technical details behind links. Facts: `scratchpad/insp-nightshift-live.md`.

## Global Constraints
- Untouched: `night-shift/`, `domain/dispatch/*`, `lib/simulation/engine.ts` + `runner.ts` (used, not changed), `lib/aiHarness/*` (used), `seed-world*`, `loadWriter.ts`, `lib/sheet/*`. Additive schema only (`DemoStory`).
- Every demo write goes through existing services: assignment creation via the existing route (from the portal), agent switch via `applyAgentSwitch`, commands via `queueCommand`, sim modes via the sim engine's `SimDriverState`, runner via `startRunner/stopRunner`, harness via `enqueueRun`, load status via `applyStatusChange`/`transitionAssignment`.
- Demo routes are `DEMO_MODE`-gated (404 otherwise), dispatcher session only, org-scoped; the driver-reply proxy posts to `${WORKER_URL}/d/${driverToken}/reply` and nowhere else.
- Nothing external can be contacted: demo policy `shadow: true`, `customerEmailOn: false`, `bossCallOn: false`; the customer sink address ends in `.invalid`; the UI says "demo sink — no email left the system".
- Presenter copy is plain business language; no "score", "rank", "engine" words on the presenter surface; AI Lab/tool details only behind "How it works" links.
- Implementers: no git writes, no subagents, never read/print `.env`; comments state rules, not history.
- Checks: backend targeted vitest + `npx tsc --noEmit` + full suite once (baseline 192 files); portal vitest (baseline 125 / 1371) + vue-tsc + build.

### Task 1 (backend): DemoStory schema, fixtures, reset, observe, actions, routes
**Schema (additive):**
```prisma
model DemoStory { orgId String @id; org Org @relation(fields: [orgId], references: [id])
  stage String @default("uncovered")   // uncovered | ai_recommendation | awaiting_approval | in_transit | breakdown_detected | driver_contacted | awaiting_driver_reply | escalated | awaiting_customer_update | customer_updated | resolved | delivering | delivered | error
  loadId String?  driverId String?  assignmentId String?  runId String?  experimentId String?  policyId String?  customerId String?
  recommendedDriverId String?  recommendationSource String?   // "ai" | "engine"
  breakdownAtFraction Float @default(0.4)  holdStartedAt DateTime?  log Json @default("[]")  error String?
  startedAt DateTime?  updatedAt DateTime @updatedAt }
```
`resetDb` gets `demoStory` before `org`.
**Fixtures (`fixtures.ts`, exact):** `DEMO_LOAD_REF = "DEMO-CHI-DET"`, `DEMO_DRIVER_EXTERNAL_ID = "DEMO-JOHN"`, driver `John Carter` (`email demo.john.carter@<org.id>.demo.invalid`, `phone "+15550100001"`, `cdlClass "A"`, `equipmentTypes ["DryVan","Reefer"]`, `languages ["en"]`, `homeBase "Chicago, IL"`, HOS full: drive 660, window 840, cycle 3600, minutesSinceBreak 0, position 20 mi west of the Chicago pickup (41.88, -87.98), `status "available"`, `DriverAvailability { acceptingLoads true, availabilityStatus "AVAILABLE", locationSharingEnabled true, source "manual" }`), customer `Demo Customer` (`primaryEmail "demo-customer@example.invalid"`, `requiresDelayNotification true`, `priority "high"`), agent policy `Demo (fast)` (`stopMin 1, delayMin 5, darkMin 10, darkAtStopMin 10, offRouteMi 3.1, offRouteMin 10, rungGapMin 1, maxCalls 0, shadow true, customerEmailOn false, bossCallOn false, dispatcherEmail = the org's first dispatcher email`), AI experiment `Demo` (`promptVersion "dispatch-v2"`, default config), ten historical loads `DEMO-HIST-01..10` Chicago → Detroit (DryVan) completed by John over the last 60 days, 9 on time / 1 late by 25 min (real geocoded stops, appointments, `Assignment status completed`), the demo load `DEMO-CHI-DET`: DryVan, `customerName "Demo Customer"`, `customerEmail` = the sink, `customerId`, stops Chicago (`"2100 S Western Ave, Chicago, IL 60608"`, 41.8532, -87.6857) → Detroit (`"1 Woodward Ave, Detroit, MI 48226"`, 42.3290, -83.0450), `geocodeStatus "ok"`, `dwellMin 45`, pickup appointment `windowStart = now + 30 min`, `windowEnd = now + 3 h`, delivery appointment `windowEnd` set AFTER creation to `suggestForLoad(...)`'s row for John `etaMs + 25 min` (tight: a stop of ≥ 15 sim-min makes the live ETA miss it; fall back to `now + 7 h` when no feasible row), `agentEnabled false`, `agentPill "off"`, `status "open"`, `revenueCents 185000`. A pool tractor `DEMO-TRK-1` and DryVan trailer `DEMO-TRL-1` (active) exist so the assignment route can pick equipment.
**Reset (`reset.ts`, idempotent, total — `resetDemo(orgId, dispatcherId)`):** in order: stop the sim runner for the org; if a story exists: cancel its AI run (`cancelRun`), if the demo load has `agentEnabled` → `applyAgentSwitch(enabled:false)` (queues the worker's `stop`), delete the demo load's `AiDecisionRecord`s (+steps cascade), `AgentEvent`s/`AgentTrip`s (loadId), `AgentUpdate`s, `LoadChange`s, `LoadLock`s, its `Assignment` (and `DispatchConflict`/`DeadheadLeg` rows if any — read `resetDb` for the child tables), the demo driver's `DriverLocation`s, `SimDriverState`, `Assignment`s (historical too — they are recreated), the ten historical loads (stops/appointments/assignments); then upsert customer, policy, experiment, driver (+HOS, availability, preference), equipment, historical loads, the demo load (keeping the SAME load row id across resets when it exists: update in place, reset status/fields, recreate stops/appointments), compute the tight delivery deadline, reset `SimulationState` for the org (`simMinutesAdvanced 0`), write `DemoStory { stage "uncovered", loadId, driverId, customerId, policyId, experimentId, log: [{ atMs, stage: "uncovered", text: "Load DEMO-CHI-DET (Chicago → Detroit) is uncovered." }] }`. Must succeed from ANY prior state, including mid-transit with a live Night Shift trip and a running sim.
**Observe (`observe.ts` — `observeStory(orgId, nowMs)` runs on every GET and is the story's heartbeat; pure reads + the two scripted world writes):**
- `ai_recommendation`: the run row is terminal → `awaiting_approval` with `recommendedDriverId` = proposal.driverId (source "ai"); if the run failed/incomplete/null-driver, or `!harnessEnabled()`, or the run exceeds 3 min → `recommendedDriverId` = `suggestForLoad` top feasible (source "engine") → `awaiting_approval`. Log the outcome in plain words ("AI recommends John Carter (confidence 0.85)" / "AI unavailable — using the deterministic recommendation: …").
- `in_transit`: requires assignment `in_progress` (the runner starts due assignments; if still `assigned` after start, `tick` once); when `simNow ≥ plannedStart + breakdownAtFraction × (plannedEnd − plannedStart)` → set `SimDriverState { mode: "stopped" }` for the driver, log "Truck stopped unexpectedly near <nearest place>", stay `in_transit` until Night Shift reacts.
- `breakdown_detected`: an `AgentEvent kind "anomaly"` with `evidence.kind === "unplanned_stop"` and not resolved on any trip of the demo load → log + stage; `driver_contacted`: an `AgentEvent` `action` with `evidence.kind ∈ {message, message_again, sms}` or a `would_say` event → stage `awaiting_driver_reply` (human).
- `escalated`: an `escalation` event after the reply → log "Night Shift escalated: <reason>; a customer update is proposed" (or "…no customer update was proposed (deadline not at risk)") → `awaiting_customer_update` (human) — if no draft was attached, the stage still waits for the human "Resolve".
- `customer_updated`: an `email` event (kind `customer_delay` or the shadow `would_say` with `to` = the sink) after the command → stage; then the orchestrator sets the driver's mode back to `auto` and logs "Truck moving again"; `resolved` when an `anomaly` event with `resolved: true` appears (or after 3 min of movement, log the fallback).
- `delivering`: when the assignment's progress fraction ≥ 0.98 (from plannedStart/plannedEnd vs simNow) and not yet completed: stop the runner, set `holdStartedAt`, and on every observe write ONE ping at the delivery stop (`DriverLocation.create` + `Driver.lastLat/lastLng/lastLocationAt` + `emitToDispatchers(orgId, "driver_location", …)` — same shape as the engine) — until an `action` event `evidence.kind === "arrived"` appears OR 6 real minutes pass OR the human skips; then `tick(orgId, remaining minutes)` so the engine completes the assignment (load `delivered`) → `delivered`; log "Delivered. Night Shift recorded the arrival." / "Delivered (arrival wait skipped)".
- Any thrown error → `stage "error"`, `error` text, never throws to the route.
**Actions (`actions.ts` — all record + trigger; human actions that write business data happen in the portal through the real endpoints):** `askAi(orgId, dispatcherId)`: `uncovered → ai_recommendation`, `enqueueRun({ experimentId, loadId })` (or straight to engine when disabled); `recordApproval(orgId, { assignmentId, driverId })`: verifies the assignment exists for the demo load and driver, posts the AI verdict `accept` on the run when there is one, `applyAgentSwitch(enabled: true, policyId)`, `startRunner(orgId, 3)`, stage `in_transit`, log "Approved: John Carter assigned. Night Shift is watching this load."; `driverReply(orgId, text)`: requires an `AgentTrip` for the load with a `driverToken`; `POST ${WORKER_URL}/d/${token}/reply { text }` (fetch, 10 s timeout); 503 with a clear message when `WORKER_URL` is unset or the trip is missing; log "John: \"<text>\""; `recordCustomerUpdate(orgId)`: after the portal queued `send_customer_email`, log "Customer update sent to the demo sink (shadow mode — no email left the system)"; `resolve(orgId)`: sets mode `auto` if not already, log; `skipArrival(orgId)`: switch the agent off + complete via `tick`, log; `next(orgId)`: for stages with no pending human action, performs the obvious automatic step (`uncovered → askAi`, `customer_updated → resolve`) so Auto-run works.
**Routes (`dispatcherDemoStoryRouter`, mounted under `/api/dispatcher` after the gate; `router.use("/demo/story", 404 unless DEMO_MODE)`):** `GET /demo/story` → `observeStory` then `{ story, stages: STAGES[] (id, title, narration), waitingOn: string | null, links: { cockpitLoadId, aiRunId, driverId, agentTimelineLoadId }, worker: { configured: boolean }, sim: { running, speed, simNowMs }, pill: string | null }`; `POST /demo/story/reset` → 200 `{ story }`; `POST /demo/story/action { action: "ask_ai" | "approve" | "driver_reply" | "customer_update_sent" | "resolve" | "skip_arrival" | "next", assignmentId?, driverId?, text? }` → `{ story }` (409 when the action does not fit the stage); the STAGES table (exact ids/titles): `uncovered "Uncovered load"`, `ai_recommendation "AI recommendation"`, `awaiting_approval "Human approval"`, `in_transit "In transit"`, `breakdown_detected "Breakdown detected"`, `driver_contacted "Driver contacted"` (awaiting_driver_reply shares it), `escalated "Escalated"` (awaiting_customer_update shares it), `customer_updated "Customer update"`, `resolved "Resolved"`, `delivered "Delivered"` (delivering shares it).
**Tests:** `tests/demo-story-reset.test.ts` (fixture counts and values; idempotency — run twice, same ids for the load/driver; reset from a mid-transit state with a fake in-progress assignment, sim state, trips/events, AI runs → everything cleaned and rebuilt; tight deadline computed), `tests/demo-story-observe.test.ts` (each automatic transition driven by inserting the corresponding rows/events: AI run proposed → awaiting_approval; harness disabled → engine source; sim past the breakdown fraction → SimDriverState stopped; anomaly/action/escalation/email/resolved events → stages; dock hold writes pings and completes; error capture), `tests/demo-story-actions.test.ts` (stage guards 409; approve records + switch on + runner started (stub runner); driver reply proxies to a fake worker `fetch` and 503 without `WORKER_URL`; skip completes), `tests/dispatcher-demo-story.test.ts` (routes: 404 without DEMO_MODE, shapes, cross-org).
