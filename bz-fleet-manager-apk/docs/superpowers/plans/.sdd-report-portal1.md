## Notable decisions

- **Tailwind version:** `npm i -D tailwindcss` installed v4 by default, which
  uses a CSS-first config (no `tailwind.config.js`/`postcss.config.js`,
  no `npx tailwindcss init -p`). The plan explicitly specifies the v3-style
  `tailwind.config.js` with `content`/`theme.extend` and a separate
  `postcss.config.js`, so Tailwind was pinned to `^3.4.19` to match the plan
  literally.
- **API client / auth store circularity:** `src/lib/api.ts`'s response
  interceptor needs `useAuthStore().logout()` on 401, but `src/stores/auth.ts`
  imports `api` to make the login request. Resolved with a lazy
  `await import('../stores/auth')` inside the interceptor (module-level
  static import would create a cycle); the request interceptor instead reads
  the token directly from `localStorage` (`fleet_token`, see
  `src/lib/constants.ts`), which the plan explicitly allows as an alternative
  to reading from the store.
- **Sidebar placeholders:** implemented as non-navigating, disabled
  `<span>` elements with a "Soon" badge (not routed to stub pages) — only
  `/` (Dashboard) and `/login` are real routes, per the plan's minimal
  routing surface.
- **Router guard testability:** `authGuard` is exported standalone from
  `src/router/guards.ts` and unit-tested against a fresh
  `createMemoryHistory()` router per test (reusing the real `routes` export
  from `src/router/index.ts`), avoiding vue-router's duplicate-navigation
  quirks that surfaced when re-pushing the same path on a shared router
  instance.
- Backend contract double-checked directly against
  `fleet-backend/src/routes/dispatcherAuth.ts` (login) and
  `fleet-backend/src/routes/dispatcherApprovals.ts` (`GET /overview`, which
  returns a `Record<tripStatus, count>` map) to make sure the client/types
  match the real API rather than the plan's paraphrase.
